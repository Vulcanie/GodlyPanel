# Don't Starve Together - config files and every setting (STEP-config)

Researched 2026-10-14. Facts are for the DST dedicated server (Steam app 343050), **public branch build 756039** (Steam buildid 25643504, built 2026-10-01 per https://api.steamcmd.net/v1/info/343050). The "game's own scripts" below are read from a public mirror of the shipped `scripts` folder that is tagged with each build number (https://github.com/vietnd69/dst-scripts, latest commit message `756039`, pushed 2026-10-01). Where the mirror and the Klei guides disagree, the shipped scripts win and the disagreement is called out.

Short names for sources (full URLs are in the legend at the bottom of the file; the big tables use the short tags to keep the file readable):
`[c]` customize.lua, `[o]` worldsettings_overrides.lua, `[si]` shardindex.lua, `[kg]` Klei Dedicated Server Settings Guide, `[kc]` Klei Command Line Options Guide, `[w]` DST wiki Dedicated Servers, `[sw]` DST wiki Simple Dedicated Server Setup, `[gsk1..3]` GameServerKings pages, `[mi]` modindex.lua, `[lf]`/`[lc]` forest/caves level definitions, `[sc]` servercreationscreen.lua, `[gl]` gamelogic.lua, `[gm]` gamemodes.lua.

## 0. Quick facts the panel needs (all sourced)

- Install: SteamCMD `login anonymous`, `app_update 343050 validate` (omit `validate` if mods were installed, it deletes them). Source: [w] https://dontstarve.wiki.gg/wiki/Dedicated_Server
- Windows 64-bit exe: `bin64/dontstarve_dedicated_server_nullrenderer_x64.exe`, working dir `bin64`. 32-bit: `bin/dontstarve_dedicated_server_nullrenderer.exe`. Source: Steam launch config https://api.steamcmd.net/v1/info/343050 and Klei's Windows guide https://forums.kleientertainment.com/forums/topic/64212-dedicated-server-quick-setup-guide-windows/
- Klei's own Windows start script runs one process per shard: `start dontstarve_dedicated_server_nullrenderer_x64 -console -cluster MyDediServer -shard Master` and the same with `-shard Caves` (same Windows-guide URL). The server must be started with its working directory set to `bin64` (or `bin`) ([w]).
- Cluster folder = `<persistent_storage_root>/<conf_dir>/<cluster>/`. Defaults: root `%USERPROFILE%\Documents\Klei`, conf_dir `DoNotStarveTogether`, cluster `Cluster_1`, shard `Master` ([w], [kc]). The panel can set all four with `-persistent_storage_root <absolute path> -conf_dir <name> -cluster <name> -shard <name>`.
- The server only starts online if `cluster_token.txt` is in the cluster folder (a Klei account token); offline clusters ignore it ([w] "Online vs. Offline Clusters").
- Files the game does **not** create for you: `cluster.ini` and `server.ini` are "mandatory" ([w]); a first run with no files in a fresh cluster folder is not documented to generate them (UNVERIFIED, see list). `cluster_token.txt` must come from the user. Everything else is optional.
- Graceful stop: console command `c_shutdown()` on the Master shard saves and shuts down every shard (https://www.gameserverkings.com/knowledge-base/dont-starve-together/dont-starve-together-console-commands.md). `-console` enables typing Lua into the server window ([w]).

## 1. File map (relative to the cluster folder)

```
<cluster>/
  cluster.ini            shared settings (INI)                         [kg]
  cluster_token.txt      one line, Klei token                          [w]
  adminlist.txt          one user id per line (cluster root)           [w] [gsk2]
  whitelist.txt          one user id per line (cluster root)           [w] [kg]
  blocklist.txt          one user id per line (cluster root)           [w]
  Master/                shard folder (name = the -shard argument)
    server.ini           per-shard settings (INI)                      [kg]
    worldgenoverride.lua world options (Lua table)                     [w] [si]
    leveldataoverride.lua  game-written complete level (do not hand edit) [si]
    modoverrides.lua     which mods are on + their options (Lua)       [mi]
  Caves/                 same files as Master
<install>/mods/dedicated_server_mods_setup.lua   mod download list (part of the install, not the cluster)   [gsk1]
```

Per-shard files are read from the shard folder (code reads `../worldgenoverride.lua`, `../modoverrides.lua`, `../leveldataoverride.lua` relative to the save folder, [si] and [mi]).

Template (Master shard) that the game's own generator tool also writes (https://github.com/vietnd69/dst-scripts/blob/main/tools/generate_worldgenoverride.lua):

```lua
return {
  override_enabled = true,
  worldgen_preset = "SURVIVAL_TOGETHER",
  settings_preset = "SURVIVAL_TOGETHER",
  overrides = {
    -- winter = "shortseason",
  },
}
```

Rules the code enforces (https://github.com/vietnd69/dst-scripts/blob/main/shardindex.lua and https://github.com/vietnd69/dst-scripts/blob/main/gamelogic.lua):
- Order of application (read from `SetServerShardData`): `leveldataoverride.lua`, if present, first replaces the saved world options. Then `worldgenoverride.lua` (only if `override_enabled = true`) is applied: if BOTH a worldgen preset and a settings preset resolve (or `preset` is given and valid for the shard), the preset data plus `overrides` REPLACE the world options; if only one resolves or none, the `overrides` are MERGED into what is already there. The wiki claims leveldataoverride wins when both files exist (https://dontstarve.wiki.gg/wiki/Dedicated_Server); the code reads the other way for a complete preset pair. UNVERIFIED in practice, so never ship both files.
- Sanity check at load prints `WARNING! Found entry '...' in worldgenoverride.lua, but this isn't a valid entry.`, `... doesn't match any known option. Did you make a typo?`, `... not a valid value. Use one of {...}.` - good text to grep in the server log.
- Worldgen options only change the map when a world is generated. World-settings options (section 7a) are copied into the running world on every load (`DoInitGame` copies `options.overrides` into the world's overrides, and the `Pre`/`Post` settings functions run at load). This is inferred from the source, not tested on a live server.
- Options marked "Set on Master" are master-controlled: the Master shard's value is sent to the Caves ("When set on the master server, they will automatically be sent to the caves server", Klei 2022 update note quoted at https://www.gameserverkings.com/knowledge-base/dont-starve-together/dont-starve-together-world-settings.md ). Setting them in the Caves file is unnecessary.
- Removed/old keys in Klei's 2016 example (do NOT use): `prefabswaps` (not an option any more, only `prefabswaps_start`), `season_start` values `autumnorspring` / `winterorsummer` (current values are `autumn|spring`, `winter|summer`, `autumn|winter|spring|summer`), `disease_delay` (deprecated, silently accepted).

## 6. leveldataoverride.lua

Written by the game client when a world is configured in the Host screen. Required fields (assert in shardindex.lua): `id`, `name`, `desc`, `location`, `overrides`. Klei does not document the format and the wiki recommends generating it with the client and copying it (https://dontstarve.wiki.gg/wiki/Dedicated_Server). Not a hand-edited file: not catalogued setting by setting.

## 7. worldgenoverride.lua `overrides` table - every option the game knows (236)

Generated from the game's own option tables (`map/customize.lua`, the lists `WORLDGEN_GROUP` and `WORLDSETTINGS_GROUP`), so key spelling, defaults and value lists are exactly the shipped ones. Labels are the in-game English names (taken from `STRINGS.UI.CUSTOMIZATIONSCREEN` in https://github.com/vietnd69/dst-scripts/blob/main/strings.lua ; the game's own spellings, including typos such as "Anenemies", are kept). Value labels in brackets are the in-game slider words. Frequency scale: `never` (None) < `rare` (Little) < `default` < `often` (More) < `always` (Tons); worldgen scale adds `uncommon` (Less), `mostly` (Lots), `insane` (Insane). Regrowth scale: `never`, `veryslow`, `slow`, `default`, `fast`, `veryfast`. Season lengths: `noseason`, `veryshortseason`, `shortseason`, `default`, `longseason`, `verylongseason`, `random`. All values are strings, e.g. `winter = "shortseason"`. A column "type" of `enum` means only the listed values pass the game's own validator; the game logs a warning for other values.

Where a row says "(Forest/Master world only)" or "(Caves world only)" the option does nothing in the other world. "Set on Master" = master-controlled option, the value from the Master shard is used.

## 8. modoverrides.lua (one per shard; enables mods and sets their options)

Optional; omitting it enables no mods in that shard (https://dontstarve.wiki.gg/wiki/Dedicated_Server). On a dedicated server the mod index first switches every mod off ("We assume the mods will be re-enabled by the modoverrides.lua file", `modindex.lua`), so a mod that is downloaded but not listed here does not run. It must `return` a table; the log says `SUCCESS: Loaded modoverrides.lua`, or `ERROR: Failed to run code from modoverrides.lua` (not a table / forgot `return`), or `Warning: modoverrides.lua is empty, or is failing to return a table.` (https://github.com/vietnd69/dst-scripts/blob/main/modindex.lua ; https://www.gameserverkings.com/knowledge-base/dont-starve-together/dont-starve-together-server-mods.md ).

Both shards (Master and Caves) read their own copy; keep them identical, otherwise players fail when moving between surface and caves (same GameServerKings pages).

--- | --- | --- | --- | --- | --- | --- | ---
`["workshop-<WorkshopID>"]` (or `["<folder name>"]` for a hand-installed mod) | Mod entry | One entry per mod. The key for a Steam Workshop mod is the literal text `workshop-` followed by the Workshop id (v1 and v2 mods are both named this way). A hand-installed mod uses its folder name under `mods/`. | Mods | none | table | `{ enabled = ..., configuration_options = {...} }` | https://dontstarve.wiki.gg/wiki/Dedicated_Server , https://github.com/vietnd69/dst-scripts/blob/main/modindex.lua
`enabled` | Mod on/off | `true` switches the mod on in this shard, `false` switches it off. ## 9. dedicated_server_mods_setup.lua (the download list)

Lives in the **server install** at `mods/dedicated_server_mods_setup.lua` ("next to bin64"), not in the cluster folder (https://www.gameserverkings.com/knowledge-base/dont-starve-together/dont-starve-together-server-mods.md ). It is a Lua script run on boot; Klei's shipped file explains itself in comments. Two functions (https://dontstarve.wiki.gg/wiki/Dedicated_Server):

key | label | description | group | default | type | allowed values | source URL
--- | --- | --- | --- | --- | --- | --- | ---
`ServerModSetup("<id>")` | Install one Workshop mod | Downloads and installs the Workshop mod with that id at server start. The argument is a **string**. The mod ends up named `workshop-<id>`. Updates are fetched only at start, only when the Workshop version changed. | Mods | none | Lua call | a Workshop file id (the number after `?id=` in the Workshop URL) | https://dontstarve.wiki.gg/wiki/Dedicated_Server , https://www.gameserverkings.com/knowledge-base/dont-starve-together/dont-starve-together-server-mods.md
`ServerModCollectionSetup("<id>")` | Install a whole collection | Installs every mod in a Workshop collection. You still must enable each mod in `modoverrides.lua`. | Mods | none | Lua call | a Workshop collection id | same sources

Safety notes: a syntax error in this file stops the server (`#ERROR: Failure to load dedicated_server_mods_setup.lua` then `#Shutting down`). Launch flags related to it: `-skip_update_server_mods` (start without checking mods), `-only_update_server_mods` (update then exit), `-ugc_directory <path>` (where v2 mods are stored; default is per shard, wasting disk, so a shared `../ugc_mods` is recommended) (https://dontstarve.wiki.gg/wiki/Dedicated_Server). Mods must be changed with the server stopped; a restart installs them. Clients must also have the mod (Workshop auto-downloads for players); players are kicked with "Disconnected Due To Missing Mods" if the server mods are older than the Workshop version.

## 10. Master-only vs both-shards cheat sheet (for the form)

- `cluster.ini`, token, admin/white/blocklists: cluster root, shared by every shard.
- Per shard: `server.ini` (ports, is_master), `worldgenoverride.lua`, `modoverrides.lua`.
- World-settings options marked "Set on Master" only need to be in the Master's file.
- Caves-only options (`world` column "Caves world only") belong in the Caves file; Forest-only options in the Master file. Options valid in both worlds (e.g. `weather`, `grass`) can go in either; the Forest ones are inert in the Caves.
