# Squad (store 393380 / dedicated server tool 403240) - modded servers
Researched 2026-10-15. Read-only web research, nothing installed or run.
Build context: Squad moved to Unreal Engine 5.5 in v9.0 (Sept 2025); Workshop titles in Oct 2026 say "v10.6" (Steel Division "UPDATED FOR v10.6", More Layers Pack "[10.6]"). The official wiki pages quoted below date from the UE4 era (the "Outdated" template is on some); everything the wiki says about folder layout was cross-checked against 2026 hosting guides and a maintained Docker image script, which still use the same layout. Raw wiki wikitext is saved in `raw\wiki-*.txt` (fetched through the fandom MediaWiki API; the normal web pages return HTTP 402/403 to the fetch tool).

## 1. Verdict: YES, a supported server mod path exists (Steam Workshop, anonymous login)
Squad mods are Steam Workshop items under app 393380 (the store app, not the server tool 403240). A dedicated server runs them when the mod folder sits in `<server root>\SquadGame\Plugins\Mods\<WorkshopID>\`. There is NO mod id list in the launch line and NO mod id list in `Server.cfg` (see "What does not exist" below). The dedicated server does NOT download Workshop mods by itself; the host must fetch them (SteamCMD `workshop_download_item`) and put them in that folder.

## 2. How mods get onto the server (sourced)
### 2a. Official wiki procedure (Squad wiki, "Uploading a mod to a dedicated server")
Source: https://squad.fandom.com/wiki/Uploading_a_mod_to_a_dedicated_server (read via API: https://squad.fandom.com/api.php?action=query&prop=revisions&rvprop=content&rvslots=main&titles=Uploading_a_mod_to_a_dedicated_server&format=json) , last edited 2024-04-15.
Manual: copy `<root steam folder>/steamapps/workshop/content/393380/<modid>` from a PC that subscribed, into `<server root>/SquadGame/Plugins/Mods` (create `Plugins` and `Mods` if missing), restart the server. "When the Server boots up, it prints out all of the Squad maps added. After that it will print all the modded maps that were added."
SteamCMD (marked "advanced", "squad server must not be running"; works only for Workshop-published mods), quoted batch:
```
SET STEAMCMD="C:\steamcmd\steamcmd.exe"
%STEAMCMD% +login anonymous +force_install_dir "C:\servers\squad_server" +app_update 403240 validate +quit
%STEAMCMD% +login anonymous +force_install_dir "C:\servers\squad_server" +workshop_download_item 393380 1205163003 +quit
@RD /S /Q "C:\servers\squad_server\SquadGame\Plugins\Mods\1205163003"
xcopy /S "C:\servers\squad_server\steamapps\workshop\content\393380" "C:\servers\squad_server\SquadGame\Plugins\Mods\"
```
Meaning: SteamCMD puts the item in `<installdir>\steamapps\workshop\content\393380\<id>`; it must be copied to `SquadGame\Plugins\Mods\<id>`; delete the old copy first for a clean update. Multiple mods = repeat the `workshop_download_item` line per id (the page's multi-mod example does exactly this, one SteamCMD call per id).
`+login anonymous` works for Workshop downloads here (wiki + Docker script below).

### 2b. Independent confirmation by a maintained server image (CM2Walki/Squad, used by many hosts)
Source: https://raw.githubusercontent.com/CM2Walki/Squad/master/bullseye/etc/entry.sh and .../bullseye/Dockerfile (I read the full text via curl). Dockerfile: `ENV STEAMAPPID 403240`, `ENV WORKSHOPID 393380`, `ENV MODPATH "${STEAMAPPDIR}/SquadGame/Plugins/Mods"`, `ENV STEAM_BETA_APP 774961`. entry.sh on every start: (1) deletes every purely-numeric folder in MODPATH, (2) for each id in the `MODS` array runs `steamcmd.sh +force_install_dir <dir> +login anonymous +workshop_download_item 393380 <id> +quit`, then (3) `ln -s <dir>/steamapps/workshop/content/393380/<id> <MODPATH>/<id>` (a link, not a copy). Then it starts the server with no mod-related argument at all (args are MULTIHOME, Port, QueryPort, RCONPORT, FIXEDMAXPLAYERS, FIXEDMAXTICKRATE, beaconport, RANDOM). Docker README format: `MODS="(13371337 12341234 1111111)"`, a bash array, ids separated by spaces (https://hub.docker.com/r/cm2network/squad).
=> Proof that (a) anonymous SteamCMD can download Squad Workshop items, (b) the only server-side requirement is the numeric id folder inside `SquadGame/Plugins/Mods`, (c) a link works as well as a copy (Linux), (d) no launch argument is needed.

### 2c. Hosting-panel behaviour in 2026 (secondary, consistent with the above)
- GameCP Pterodactyl egg: variables `WORKSHOP_ITEMS` (default empty, "Steam Workshop mod IDs separated by commas") and `WORKSHOP_UPDATE` (default `1`, "Automatically download and update workshop mods listed in Workshop Mods on startup"); install script "moves Workshop mods to the correct directory". https://gamecp.com/templates/game/squad
- Game Host Bros: "Workshop Mods" comma-separated ids, "The server downloads and loads the mods at startup", removing an id and restarting uninstalls it. https://www.gamehostbros.com/guides/games/squad/install-mods (updated 2026-10-07)
- XGamingServer: mods download "via SteamCMD into `SquadGame/Plugins/Mods` on the next restart"; panel also auto-adds dependencies (their feature, not a game feature). https://xgamingserver.com/docs/squad/install-mods
- PingPlayers: upload to `/Server/SquadGame/Plugins/Mods`. https://pingplayers.com/knowledgebase/squad/how-to-add-mods-to-your-squad-server
- LOW.MS: "Squad will not load a mod if it is nested one folder too deep" (the folder `Mods\<id>` must directly contain the mod, i.e. the `Content` folder, the `.uplugin`, `modinfo.smi`). https://low.ms/knowledgebase/squad-save-location-how-to-upload
- Mod folder contents (client page, same wiki family): "mod folder (which contains a Content folder, a <mod_name>.uplugin file, and a modinfo.smi file)". https://squad.fandom.com/wiki/Playing_a_Mod

## 3. Config lines / launch arguments that enable mods
### Launch line: none
Wiki "Server Configuration" lists the entire documented command line: `MULTIHOME`, `Port`, `QueryPort`, `beaconport`, `RANDOM`, `FIXEDMAXPLAYERS`, `FIXEDMAXTICKRATE`, `PREFERPREPROCESSOR` (UNTESTED per wiki), `-log`, `-fullcrashdump`. Nothing mod related. https://squad.fandom.com/wiki/Server_Configuration (edited 2025-12-08). The Docker image confirms the server runs mods with those same arguments only.

### `SquadGame\ServerConfig\ModsConfig.cfg`: optional, mod-specific, NOT a mod list
One Workshop mod author documents it: SquadExtendedUtilities (Workshop 3787754942): "You have to add in \SquadGame\ServerConfig\ModsConfig.cfg this line, or add mod id to enable some features. `ModLoadOrder=3787754942`". Source: Steam Workshop API description of that item (https://steamcommunity.com/sharedfiles/filedetails/?id=3787754942 , fetched via ISteamRemoteStorage/GetPublishedFileDetails). Game Host Bros says the same ("some mods need their ID added to `ModsConfig.cfg`"). The file is NOT in the official wiki's list of ServerConfig files, and I found no official doc of its syntax. So: key `ModLoadOrder`, value a Workshop id; whether several ids go on one line, several lines, or comma separated, and whether it is created by the server, is UNVERIFIED.

### What does NOT exist (the brief mentioned "Mods.cfg / ModList")
- No file called `Mods.cfg` or `ModList` found anywhere (searched several ways; the official wiki list of ServerConfig files has none: Admins.cfg, Bans.cfg, CustomOptions.cfg, ExcludedFactions.cfg, ExcludedLayers.cfg, ExcludedLevels.cfg, LayerVoting.cfg, LayerVotingNight.cfg, LayerVotingLowPlayers.cfg, LayerRotation.cfg, LevelRotation.cfg, License.cfg, Motd.cfg, Rcon.cfg, RemoteAdminListHosts.cfg, RemoteBanListHosts.cfg, Server.cfg, ServerMessages.cfg, VoteConfig.cfg).
- The official `Server.cfg` sample on the wiki has no mod key. LOW.MS claims "find the mods section [in Server.cfg] and add the mod IDs as a comma-separated list" but does not name a key; that is a panel (TCAdmin) feature and contradicts the wiki, so treat as UNVERIFIED/unreliable. LOW.MS and others also mention a `Layers.cfg`, which is not a Squad file per the wiki list; ignore.
- No launch argument for mods (e.g. no `-AdditionalModDirsToCook`; that name is not documented anywhere I could find).

## 4. Custom layers / maps
- Mods that add maps/layers add new layer ids; they are not usable until the layer id is in the rotation. Which file depends on `MapRotationMode` in `Server.cfg` (wiki values shown in the sample: `LayerList`, `LayerList_Vote`, `LayerList_Randomized`, also LevelList / LevelList_Randomized): `LayerVoting.cfg` (+ `LayerVotingLowPlayers.cfg`, `LayerVotingNight.cfg`) with `MapRotationMode=LayerList_Vote` (the default on a fresh install per wiki: "The default Map Rotation Mode for a freshly installed server will be set to Layer Voting"); `LayerRotation.cfg` for `LayerList`; `LevelRotation.cfg` for the level modes. One layer per line. Sources: https://squad.fandom.com/wiki/Server_Configuration and https://www.gamehostbros.com/guides/games/squad/install-mods .
- Layer ids are the exact names the mod publishes on its Workshop page, case as written, e.g. `Chornivsk_AAS_v1`, `Chornivsk_RAAS_v1` (https://steamcommunity.com/sharedfiles/filedetails/?id=3726472400), `MLP_AlBasrah_RAAS_v1` (More Layers Pack, id 3570870614), `SDCL_Anvil_Invasion_v1` (id 3775873211). Wiki naming convention for creators: `MapName_GAMEMODE_versionnum_EXTRAINFO`, e.g. `OPFirstLight_AAS_v3_HELI` (https://squad.fandom.com/wiki/Creating_a_Custom_Map_Layer). Factions can be appended on a line ("Anvil_AAS_v1 USA RDF"), wiki Server Configuration, "Other Rotation Modes".
- Admin console equivalents work with modded ids: `AdminChangeLayer <layer>` / `AdminSetNextLayer <layer>` (wiki; and Workshop pages tell admins to use `adminchangelayer_<layer>`). Wiki: "If you want to explore the map solo ... type in any of the gameplay layers" (Training).
- Excluded lists apply to modded content too: `ExcludedLayers.cfg`, `ExcludedLevels.cfg`, `ExcludedFactions.cfg` ("This can be done for mods and Vanilla", wiki).
- Workshop item tags that tell the admin what a mod supports: "Map Layers", "Voting Compatible", "Vanilla Rotation Compatible", "Plugin", "Co-op Missions", "Total Conversion" (read from the item details API for the 30 top trending items).
- Faction acronyms changed in 9.0 (MEA -> GFI, Insurgents -> MEI): affects rotation lines with factions (https://www.joinsquad.com/updates/squad-9-0-release-notes).
- Server browser: wiki "Server licensing": unlicensed/modded servers live in the "Custom Servers" list; "Find Match" "Only shows modded servers if the player has these mods installed". Server `Tags=` line in `Server.cfg` (space separated, e.g. `Tags= language_en mode_aas ...`) is for filters (wiki). G-Portal: "at least two layers in the map selection" or the server may not show (https://www.g-portal.com/wiki/en/?p=4327; hosting-provider claim).

## 5. How clients must match
- Players need the same Workshop items and versions. In the server browser a wrench icon marks modded servers and lists required mods; joining without them shows "The following mods are missing or out of sync:" with a DOWNLOAD ALL button (https://squad.fandom.com/wiki/Playing_a_Mod, flagged Outdated but the flow matches the hosts' warnings). XGamingServer: mismatched versions block joining. LOW.MS: uploading to the server "does not push it to your players".
- A server can only keep up with a mod if it re-downloads when the author updates: both the wiki script and the Docker image re-fetch every start. After a Squad game update, mods must be re-cooked: 9.0 notes "all mods will need to be re-cooked with the v9.0 SDK". Mods published for old versions still sit in the Workshop (e.g. Wil's Fools Road tagged "SQ v8.2", last updated 2025-06-27, 2.2 GB) and may fail; the wiki troubleshooting for "Mod not loaded" is only "Remove the mod(s), and delete the SteamCMD download cache. Then re-download." (https://squad.fandom.com/wiki/Unable_to_load_a_Layer)
- Mods are large. Item sizes (Workshop API, Oct 2026): Steel Division 16.2 GB, FBG MODE 10 GB, IWMAP 5.5 GB, Chornivsk 1.6 GB, More Layers Pack 134 MB, ModLoader 3.2 MB, TF Layers 31 MB. The panel should warn about disk and first-start time.

## 6. Plugin / mod-loader ecosystem
### In-game (server-side) Workshop mods
- ModLoader (Workshop 3516838562, "ModLoader [3MB] [10.5]", 91,279 subscribers, updated 2026-06-17): framework that lets other mods run without cooking custom layers. How: load its layer `ModLoader_v1` (or the `ModLoaderInit` mission) and list mods in `Squad\SquadGame\Saved\ModLoader\ModLoader.json` (a JSON array named `mods`). A companion "ModLoader Suite" (3523300403, updated 2026-08-05). Source: the item description via the Steam API. Server-side location of that JSON on a dedicated server (`<server root>\SquadGame\Saved\ModLoader\ModLoader.json`) is by analogy, UNVERIFIED.
- Mods that must be "initialised" by a first layer: Squad AdminTools/VoiceConnect (3193475024, title currently says "NOT WORKING"; needs layer `VoiceConnect_Init` first in rotation), SquadExtendedUtilities (initialise via `SEUInit` map plus the `ModsConfig.cfg` line; 23,282 subscribers, updated 2026-10-13). So some mods need a specific layer first in the rotation list.
- Companion mods can depend on another mod (e.g. Community Layers For Steel Division requires Steel Division): the admin must list every needed id; SteamCMD `workshop_download_item` itself does not resolve dependencies (general SteamCMD behaviour; the panels' auto-dependency features are their own) - UNVERIFIED for Squad specifically.

### External tools (not mods; run beside the server)
- SquadJS (https://github.com/Team-Silver-Sphere/SquadJS): Node.js scripting framework, licence BSL-1.0, 197 stars, not archived; last push 2026-10-06 (merged "fix(db-log): upsert Epic players on eosID"); last tagged release v4.2.0 on 2024-08-11, so the live `master` branch is ahead of the release. Built-in plugins (README, as of 2026-10-15): auto-kick-unassigned, auto-tk-warn, cbl-info, chat-commands, db-log, discord-admin-broadcast, discord-admin-cam-logs, discord-admin-request, discord-chat, discord-debug, discord-fob-hab-explosion-damage, discord-killfeed, discord-placeholder, discord-rcon, discord-round-winner, discord-roundended, discord-server-status, discord-squad-created, discord-subsystem-restarter, discord-teamkill, fog-of-war, intervalled-broadcasts, seeding-mode, socket-io-api, team-randomizer. Discord needs a bot token; db-log needs a SQL database.
- Others listed on the official wiki "Server Administration Tools" (https://squad.fandom.com/wiki/Server_Administration_Tools): BattleMetrics RCON (web UI, proprietary), SquadMS (MIT, Laravel web UI), Squad Control Panel / SQCP (MIT, Node+Vue).
- Server licensing (wiki): a licence key in config puts a server in the main list; licensed servers must be 60+ slots and not run custom rules/mods per the guidelines ("Use the vanilla Squad game mode rules"). Modded servers are normally unlicensed "Custom Servers". Page is old (2016-era text), details UNVERIFIED for 2026.

## 7. Risks / gotchas
- Anti-cheat: wiki/hosts mention EasyAntiCheat nowhere for the server mods path; whether the dedicated server enforces client mod integrity beyond version matching is UNVERIFIED.
- Savegames: Squad has no persistent world save, so mod removal does not break a save; only the rotation files break if they list layers of a removed mod ("Typo in the layer name"/"Unable to load a Layer" in the wiki troubleshooting). Keep a vanilla rotation as fallback (LOW.MS advice).
- Rotation files can be restored by `validate` on update: wiki says "updating the server using the validate option may restore the file" for `LayerVotingLowPlayers.cfg`. Panel should not run `validate` over custom rotation files without a backup.
- Existing windows approach is a copy (wiki `xcopy`); on Windows a directory junction (`mklink /J`) avoids duplicating up to 16 GB. Docker image proves a link works on Linux; junction on Windows is my suggestion, UNVERIFIED for Squad.
- Mods need re-cook after each major engine/SDK version; many Workshop mods are abandoned. Show "last updated" before adding.
- Stop the server before replacing mod files (wiki: "the squad server must not be running").

## 8. Recommendation for GodlyPanel
1. Offer a `mods` field in the create form: a list of Workshop item ids (numbers separated by commas/spaces; validate digits only). Optional and empty by default (vanilla works with no extra steps).
2. Generate the start script so that, before launching `SquadGameServer.exe`, it (a) runs `steamcmd +force_install_dir "<server dir>" +login anonymous +workshop_download_item 393380 <id> +quit` for each id (one call per id, as the wiki does; note it uses the Squad STORE id 393380 here, not the server id 403240), (b) clears the old `SquadGame\Plugins\Mods\<id>` and puts the downloaded `steamapps\workshop\content\393380\<id>` folder there (copy as the wiki does, or junction), (c) starts the server with the normal arguments. No mod flag exists, so the launch line does not change. Only update on start (as the Docker image and GameCP egg do); add an "update mods on start" toggle defaulting on, mirroring `WORKSHOP_UPDATE`.
3. Do not auto-edit `LayerVoting.cfg`/`LayerRotation.cfg`; show a note: "Add the mod's layer names (from its Workshop page) to LayerVoting.cfg (or LayerRotation.cfg when MapRotationMode=LayerList), then restart." Optionally a text area that appends layer lines to the right rotation file, picked from `MapRotationMode`.
4. Optional second field: ModsConfig.cfg `ModLoadOrder` lines, only after the syntax is confirmed (see UNVERIFIED #1). Until then, link the user to the mod's Workshop page.
5. Players must subscribe to the same mods; surface that as a hint in the UI.
6. Mod loader install step: not needed (ModLoader is just another Workshop id). SquadJS is separate; if offered at all, it is a later, optional add-on (needs Node 18, Yarn, Discord/DB config), not part of basic mod support.
