## Root cause and verified fix for 4, 5, 6

`SCUMServer.exe` asks for `highestAvailable`. The panel runs non-elevated, so it cannot read the path, close, or kill the elevated game. Putting `set __COMPAT_LAYER=RunAsInvoker` before the `start` line makes Windows run it with the panel's own token. Verified: no UAC prompt, process visible in 4 s with its path, `online:true`, graceful stop works, game runs fine non-elevated (world loads, ports bind, saves). If the panel itself ever runs elevated this is harmless.

## Discrepancies to fix

1. `src/server/data/games/scum.js` `buildStartScript` (around line 63): add a line `set __COMPAT_LAYER=RunAsInvoker` after `cd /d "%~dp0"`. Check the launch-line editor (`parseLaunchArgs`) and `buildStartScriptFilename` consumers keep unknown lines such as this `set` line when rewriting the script (my test edited the bat by hand, not through the editor).
2. `scum.js` `implicitPorts` (lines 56 to 59) and the comment at lines 61 to 62: replace with the verified layout. Suggested: pass `-QueryPort=<port+1>` in the script (verified to work) so several SCUM servers or other Steam games do not fight over UDP 27015, and declare `{offset:1, UDP, "Steam server list query"}` and `{offset:2, TCP, "game port + 2, opened by the server"}`. Without `-QueryPort`, declare UDP 27015 as a fixed port (not an offset). Also add `-QueryPort` to the launch catalog (`ui/src/catalog/games/scum.js`) as managed (notes deviation 3 said UNVERIFIED: it is verified now). Dossier `03-launch-args.md` row `-QueryPort` and the "UDP 7778 raw socket (game+1)" sentence are wrong for this build.
3. First-start problem (check 9): the panel cannot seed name/password on the very first start. Options for the lead: (a) tell the user in the guide notes and in the creation result that SCUM replaces the file on its first run and the name/password must be set after the first start (the Settings tab only works after that anyway, and the file is only read at start); (b) have the panel start the server once and write the three keys after the first stop. Adding `scum.ServerSettingsVersion=7` does NOT help (tested). Update `05-implementation-notes.md` "What the template does" (`buildConfigFile` ... before the first start) and the guide note accordingly.
4. `src/server/services/serverControl.js` `stopGraceMs`: add `scum` with 30 s (graceful exit took 13 to 14.6 s of the 15 s default; the notes' worry about 15 s was justified).
