# Barotrauma: implementation notes

Files (new only, nothing registered in index.js, no existing file touched):
- `src/server/data/games/barotrauma.js` (template, backup, logs, launchOptions: true)
- `ui/src/catalog/games/barotrauma.js` (type, title, files: {}, launch, guide)
- `tests/unit/game-barotrauma.test.js`, `ui/src/__tests__/game-barotrauma.test.js`
To register: add `import barotrauma from "./barotrauma.js"` and `barotrauma` to `GAME_MODULES` in `src/server/data/games/index.js`, and the UI module in `ui/src/catalog/games/index.js`.

## PROMINENT LIMITATIONS
1. **No graceful stop.** The console takes `exit` / `quit` / `close` only from a real console's keyboard (`Console.KeyAvailable/ReadKey`) and prints "Redirected input is detected but is not supported ... Input will be ignored." The panel's Stop (close the window, force-kill after the grace time) is the only stop. No RCON/REST exists. What a closed window does on Windows (whether `Quit()` runs and rewrites serversettings.xml, saves the ban list and the server log) is UNVERIFIED: `ShouldRun = false` on process exit is wired only under `#if LINUX`. A campaign is saved at creation and at the end of every round (not in `Quit()`), so a forced stop loses only the round in progress, plus the round's server log. The warning is shown on creation, in the template description and in the guide.
2. **Saves are outside the install folder.** Campaign saves are in `%LocalAppData%\Daedalic Entertainment GmbH\Barotrauma\Multiplayer` of the Windows user that runs the panel/server, shared with every other Barotrauma server on the PC and with the game itself. The panel's backup only knows the bases "working" and "install" (the server folder), so **the default backup does NOT contain the campaign saves.** Nothing new was invented: the backup list keeps what is in the folder (serversettings.xml, config_player.xml, Data/clientpermissions.xml, Data/permissionpresets_player.xml, Data/bannedplayers.txt, LocalMods, legacy Data/Saves), and the guide and the template description tell the user to add the profile folder as a custom backup path (if the panel supports one) or copy it by hand. Also: two Barotrauma servers on one PC share that save folder (campaign names can collide), and moving the folder is not possible by an argument (`-savepath` does not exist; `SavePath` in the player config is a game-config setting, not wired here).
3. **No settings file in the Settings tab.** `serversettings.xml` stores every setting as an ATTRIBUTE of one `<serversettings>` root element. `ui/src/configParsers/xmlProperties.js` only reads the `<property name= value=>` child shape, so no parser fits; no parser was written. `files: {}`. The panel also does NOT write the file (the dossier has no minimal file verified on a real install; the server writes it itself on first start and rewrites it on every in-game change and on a clean shutdown, dropping unknown attributes). Users edit it by hand with the server stopped. The sourced launch arguments carry name, ports, public, max players, password.

## What was built
- Template: id/type `barotrauma`, displayName "Barotrauma", `updateAppId` 1026340 (free tool, anonymous), `storeAppId` 602960, `installLayoutRoot: ""`, `method: "process"`, `processName` `DedicatedServer.exe` (single .NET 8 process; inferred from the single-assembly design, not observed), est. install 250 MB (depots ~220 MB).
- Fields: `sessionName`, `serverPassword`. Max players is not asked (script writes `-maxplayers 10`, clamped 1 to 16 if a value is supplied).
- Ports, both UDP: game 27215, query 27217. The game's own 27015/27016 are Core Keeper's / Sons of the Forest's defaults here. The query port is game + 2; the panel's precaution port (game + 1 = 27216) stays free. The query port is only opened by the game while the server is public.
- Start script: `start /MIN "<name>" DedicatedServer.exe -name "<name>" -port N -queryport N -public False -maxplayers 10 (-password "<pw>" | -nopassword)`. `-public False` and `-maxplayers` are written explicitly because the dossier shows code default and file default differ (IsPublic false vs true, MaxPlayers 10 vs 8). The password is on the launch line (the dossier offers the file as the alternative; the panel does not write the file). Values with `" % & | < > ^ !` or backslash or control characters are refused in `resolveParams` (`launchText`) and also stripped in the script as a second guard.
- Launch options form (`launchOptions: true`, style `space`): 15 catalog entries covering the dossier's 14 sourced flags: -name, -port, -queryport, -public, -maxplayers, -password, -nopassword (not editable, managed), -upnp, -enableupnp (alias, not editable), -playstyle, -banafterwrongpassword, -karma, -karmaenabled (alias, not editable), -karmapreset, -language. Options: -public True/False, -upnp True/False, -playstyle Serious/Casual/Roleplay/Rampage/SomethingDifferent, -karmapreset default/strict/custom, -language the 20 names from languageoptions.xml (custom allowed). No argument has to be last, so appending at the end of the line is safe.
- Backup and logs: see limitation 2; logs = `ServerLogs` folder (written at end of round and on a clean shutdown) and `servercrashreport.log`.

## Deviations from the dossier / left out
- `-lenienthandshake` left out (purpose undocumented). `-ownerkey`, `-endpoint`, `-pipes`, `-multiclienttestmode` left out (client-hosting/debug; `-ownerkey` would also stop Steam dedicated-server init).
- No `serversettings.xml` is written or offered (dossier 02 lists its attributes, but without a parser and without a verified minimal file this was left out; no setting in it is in the catalog).
- **Mods field NOT implemented.** The dossier recommends a `mods` list written into `config_player.xml`. A template field only works with the panel's existing mods machinery (`serverCreationService` resolves ids for ARK/Zomboid/Soulmask style fields) and writing `config_player.xml` before the first start would replace the game's own default config with a file it has not been checked against. The server also downloads nothing, so the mod folders would still have to be copied into `LocalMods` by hand, and a wrong path is skipped silently. It would need either edits to existing files (hook into creation) or an editor for a file that mixes game config with the mod list. Described in the guide instead: copy the folder (with `filelist.xml`) into `LocalMods`, add `<package path="LocalMods/<folder>/filelist.xml" />` under `<regularpackages>` of `config_player.xml` in load order (dependencies first) with the server stopped. Players need the same mods. LuaCs (Lua/C# mods) is not covered.
- The panel starts the server not public (`-public False`); users list it with `-public True` in Launch options. Joining by IP and game port works either way.

## MUST be verified on a real install
1. `+login anonymous +app_update 1026340 validate` works and puts `DedicatedServer.exe` in the folder root; no runtime (.NET 8, VC++) needs installing first.
2. `DedicatedServer.exe` is the single process that stays running (processName match, panel detects "running").
3. What Stop does (closing the window): process ends, whether serversettings.xml / banlist / server log are written, and that a campaign made earlier is intact after a forced stop.
4. A fresh start writes `serversettings.xml`; the launch arguments override it (name, ports, `-public False`, `-maxplayers`, password) and survive the next shutdown rewrite.
5. `-nopassword` + `-password` ordering (the code is sequential, last wins) and that a quoted password with spaces is read as one value; `-name` with spaces likewise.
6. Both UDP ports reachable through the firewall rule the panel opens; the query port opens only with `-public True`; A2S answers there (not tested; panel just watches the process).
7. Where the campaign saves land (`%LocalAppData%\Daedalic Entertainment GmbH\Barotrauma\Multiplayer`) when the panel runs as a service or another Windows user (the profile folder differs per user).
8. `config_player.xml` is created at first start and the `<regularpackages><package path=...>` form loads a mod copied into `LocalMods`.
9. Pass-2 arguments (`-playstyle`, `-karma*`, `-banafterwrongpassword`, `-language`) take effect, and whether they are written back to serversettings.xml.
10. A name over 60 characters is cut by the game (source says so; the script also cuts at 60).
