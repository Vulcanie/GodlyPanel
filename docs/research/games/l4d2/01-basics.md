# Left 4 Dead 2 dedicated server: basics (DRAFT 3, researched 2026-10-15)

Build the facts are for: Steam public branch, build id 23990100 (https://api.steamcmd.net/v1/info/222860, read 2026-10-15).
VDC = Valve Developer Community wiki (developer.valvesoftware.com). It blocks plain fetch tools (HTTP 403 / Anubis) but its MediaWiki API worked from a real browser.

## SteamCMD
- Server tool app id 222860 "Left 4 Dead 2 Dedicated Server", type Tool, freetodownload=1, parent 550; Windows depot 222862 (161 MB), Linux 222863, common depot 222861 (9.55 GB). Source: https://api.steamcmd.net/v1/info/222860
- VDC Dedicated Servers List row: "Left 4 Dead 2 Dedicated Server 222860, SteamCMD Yes, Steam Client Yes, Anonymous Login Yes". Source: https://developer.valvesoftware.com/wiki/Dedicated_Servers_List
- NOTE: 222840 is the OLD Left 4 Dead (1) dedicated server, not L4D2 (same VDC list). The ZAP-Hosting guide wrongly uses 222840 for L4D2 (https://zap-hosting.com/guides/docs/dedicated-windows-l4d2). Do not copy it.
- Command (FireDaemon KB, Windows): `+login anonymous +force_install_dir "C:\L4D2" +app_update 222860 validate +quit` (https://kb.firedaemon.com/support/solutions/articles/4000086975-left-4-dead-2-source). VDC SteamCMD: `force_install_dir` must come before `login`/`app_update`; `validate` re-checks files; `quit` logs off (https://developer.valvesoftware.com/wiki/SteamCMD). Full form: `steamcmd +force_install_dir <abs path> +login anonymous +app_update 222860 validate +quit`.
- ESAGAMES shows the same shape for Linux: `steamcmd +login anonymous +force_install_dir ./l4d2 +app_update 222860 validate +quit` (https://esagames.ro/how-to-make-a-left-4-dead-2-server.php).
- Source: Steam launch entry for the app: one entry, executable `srcds.exe`, config oslist windows, no arguments field (https://api.steamcmd.net/v1/info/222860).

## Folder layout, executable, process name
- Steam's default installdir name is "Left 4 Dead 2 Dedicated Server" (https://api.steamcmd.net/v1/info/222860); with force_install_dir the folder is whatever you pass.
- Executable: `srcds.exe` (Steam launch entry above; VDC Source Dedicated Server page: "./srcds.exe -game <game> +map <map> +maxplayers X" on Windows, https://developer.valvesoftware.com/wiki/Source_Dedicated_Server). Game directory name for `-game` is `left4dead2` (FireDaemon KB; LinuxGSM `startparameters="-game left4dead2 ..."`, https://raw.githubusercontent.com/GameServerManagers/LinuxGSM/master/lgsm/config-default/config-lgsm/l4d2server/_default.cfg).
- Config location: `<install>\left4dead2\cfg\server.cfg` (ESAGAMES, SurvivalConfigs https://survivalconfigs.com/left-4-dead-2 default `C:\srcds\left4dead2\cfg\`; VDC: configs are in `<game>/cfg/`, edit `<game>/cfg/server.cfg`). The `servercfgfile` cvar defaults to `server.cfg` (VDC cvar list https://developer.valvesoftware.com/wiki/List_of_Left_4_Dead_2_console_commands_and_variables).
- Logs go to `logs` inside the game directory by default (cvar `sv_logsdir` default `logs`, `sv_logfile` default 1, same cvar list).
- Process name the panel must match: `srcds.exe` (a single process; nothing contradicts a launcher/shipping split, but that was not seen in any source). Note many Source servers run as `srcds.exe`, so never kill by image name (see "Panel must not").
- FireDaemon's article writes the executable as `C:\L4D2\left4dead2\srcds.exe`, which conflicts with the Steam launch entry and VDC (exe in install root). A Steam community guide (marked removed by Steam, may be unreliable) runs `start srcds.exe -console -game left4dead2 -secure +maxplayers 4 +map c1m1_hotel` from a .bat in `C:\Steam-Server\l4d2_ds` with the `left4dead2\cfg` and `left4dead2\addons\sourcemod` folders directly below it (https://steamcommunity.com/sharedfiles/filedetails/?id=764005219). Two sources plus the Steam launch entry say srcds.exe is in the install root; treat that as right but confirm with a real install (UNVERIFIED).

## Ports (all from VDC https://developer.valvesoftware.com/wiki/Source_Dedicated_Server unless noted)
- 27015 TCP+UDP: game, pings/A2S queries, and RCON. Change with `-port`. (`hostport` cvar default 27015, cvar list.)
- 27020 UDP: SourceTV. Change with `+tv_port` (cvar `tv_port` default 27020). Only matters if SourceTV is on (`tv_enable` default 0). `-nohltv` disables SourceTV (https://developer.valvesoftware.com/wiki/Command_line_options).
- 27005 UDP: client port (`-clientport`); 26900 UDP: Steam port, outgoing (`-sport`/`-steamport`; Command line options page says `-steamport` default 26900, auth port = +1; it also says `-clientport` default 27002, which disagrees with the 27005 above. UNVERIFIED which is right).
- SRCDS also seen on 27005 and 51840 UDP, maybe outbound only (same VDC page).
- FireDaemon: use a port in 27015-27020, one per server on the same IP. ZAP: open 27015-27020 TCP and UDP. Forwarding UDP 27015 (+ TCP 27015 if remote RCON is wanted) is what a panel needs; the rest are optional.
- Servers do not answer A2S queries until a map is loaded (VDC Source Dedicated Server).

## Minimal start command
- Minimum (VDC pattern + FireDaemon): `srcds.exe -console -game left4dead2 -port 27015 +map c1m1_hotel +maxplayers 4 +exec server.cfg`. FireDaemon's full line: `-console -game left4dead2 -secure +map c1m1_hotel` then `-autoupdate +log on +maxplayers 4 -port 27015 +ip 1.2.3.4 +exec server.cfg`.
- Flags verified on VDC Command line options (https://developer.valvesoftware.com/wiki/Command_line_options): `-console` (srcds on Windows runs in console mode), `-game`, `-port` (default 27015), `-ip` (bind address; must be a local address or 0.0.0.0), `-strictportbind` (quit instead of moving ports if bind fails), `-nohltv`, `-nomaster` (hide from master list), `-insecure` (disable VAC), `+map`, `+maxplayers`, `-norestart` (srcds_run). `-autoupdate` is documented as Linux only and needs `-steam_dir`/`-steamcmd_script`, so do not use it on Windows. `-tickrate` is documented as disabled in code for L4D and L4D2.
- LinuxGSM default start line (Linux, but same engine args): `-game left4dead2 -strictportbind -ip ${ip} -port ${port} +clientport ${clientport} +map ${defaultmap} +servercfgfile ${servercfg} -maxplayers ${maxplayers}` with port 27015, clientport 27005, defaultmap c5m1_waterfront, maxplayers 8 (LinuxGSM default config URL above). Note it uses `-maxplayers` while FireDaemon uses `+maxplayers`; both are listed on VDC.
- Mode in the start line: ESAGAMES `./srcds_run -game left4dead2 +map c1m1_hotel +sv_gametypes coop -port 27015`; Steam forum helper says `sv_gametypes "versus"` in server.cfg plus the mode appended to the map command (https://steamcommunity.com/discussions/forum/13/1843566500518625515/ summary: the helper said to add "VERSUS" after the map command). VDC: `mp_gamemode` "changed using map command, eg: map mapname versus".
- Max players: vanilla co-op is 4 survivors; `survivor_limit` default 4 (cvar list). Valid values of `+maxplayers` beyond 4/8 are UNVERIFIED (ESAGAMES says `sv_maxplayers 8` is a convar, but `sv_maxplayers` is NOT in the VDC L4D2 cvar list; do not use it).

## How to stop
- LinuxGSM's L4D2 default config has `stopmode="3"`, which its stop script implements as sending the text `quit` to the server console and waiting up to 30 s before killing the session (https://raw.githubusercontent.com/GameServerManagers/LinuxGSM/master/lgsm/config-default/config-lgsm/l4d2server/_default.cfg and https://raw.githubusercontent.com/GameServerManagers/LinuxGSM/master/lgsm/modules/command_stop.sh). So `quit` is what people use for L4D2 (Linux, same engine).
- `exit` is in the VDC L4D2 command list ("Exit the engine.", cvar list). `quit` itself is not on that VDC page (searched, not found), so I never saw Valve document it; the LinuxGSM evidence is indirect. Plan: send `quit` via RCON or console stdin, wait about 30 s, only then end the process by PID. Confirm on a real install that RCON `quit` makes srcds.exe exit (UNVERIFIED).
- FireDaemon: untick "Graceful Shutdown" in the Lifecycle tab "since the server doesn't respond to it" (the KB says srcds does not react to the Windows close message). So a panel should use RCON/console `quit`, not Ctrl+C-style signals, on Windows. Source: https://kb.firedaemon.com/support/solutions/articles/4000086975-left-4-dead-2-source
- Saves on exit: nothing to save (see above). Plugin data is the plugin's concern.

## Query and remote control
- A2S (Steam server query) over UDP to the game port 27015: A2S_INFO, A2S_PLAYER, A2S_RULES (https://developer.valvesoftware.com/wiki/Server_queries). Challenge mechanism since December 2020: the server may answer with S2C_CHALLENGE ('A', 0x41) and the client must repeat the request with the number appended; A2S_PLAYER/A2S_RULES start with challenge -1. That page also carries a user note that the L4D2 server "may deny reply" for packets from the same IP in quick succession (note dated 2021-06-19), and a note that A2S_INFO on update 2.2.1.3 sometimes returns a challenge. So poll gently (every 10-30 s, not faster) and handle the challenge.
- Player count: A2S_INFO has current players and max players; A2S_PLAYER lists players. UNVERIFIED how L4D2 reports a lobby-reserved/empty server and whether `sv_visiblemaxplayers` (default -1, "Overrides the max players reported to prospective clients", cvar list) changes the A2S max.
- Source RCON over TCP on the same port as the game (27015 default, follows `-port`); first packet must be SERVERDATA_AUTH (type 3) with the password; if `rcon_password` is not set or empty every auth is refused; packet max 4096 bytes, long output split over several packets; writing `rcon_password` closes all authenticated connections; banned IPs are refused (https://developer.valvesoftware.com/wiki/Source_RCON_Protocol). Brute-force guard cvars: `sv_rcon_maxfailures` 10, `sv_rcon_minfailures` 5, `sv_rcon_minfailuretime` 30 s, `sv_rcon_banpenalty` 0 minutes (cvar list), so a panel with a wrong password can get its own IP banned: keep the password in sync.
- Does L4D2 need `-usercon` for RCON? VDC lists `-usercon` as "Enable RCON for Counter-Strike: Global Offensive and Team Fortress 2 servers" only; L4D2 works through `rcon_password` per other guides, but not proven on a real install. UNVERIFIED.

## GSLT, lobby and matchmaking
- GSLT: the ZAP guide says a token is needed for "App ID 222840" and passes it with `+sv_setsteamaccount` (that app id is L4D1 so the guide is unreliable). VDC's L4D2 cvar list has no `sv_setsteamaccount` entry (searched, not found), and VDC Source Dedicated Server only mentions the token in an error note (error 18/106 "regenerate your token... replace it in your sv_setsteamaccount startup parameter"). Newer third-party sources: 1up-servers says "The token is optional: the server runs and accepts players by address without one" and to create it for app ID 550 (https://1up-servers.com/en/blog/l4d2-dedicated-server/); ZAP-Hosting's GSLT guide says use App ID 550, one token per server, and that without a valid token servers "may not show up in the public server list or may not be able to use VAC protection" (https://zap-hosting.com/guides/docs/l4d2-gslt/). Renode: token goes on the launch line as `+sv_setsteamaccount`, not in server.cfg (https://www.renode.space/blog/steam-game-server-tokens-gslt, search snippet only). Whether Valve requires it for L4D2 is UNVERIFIED (no Valve source found); treat as optional, app id 550 if used, one token per server.
- `sv_allow_lobby_connect_only`: VDC default 1, "If set, players may only join this server from matchmaking lobby, may not connect directly." (cvar list). commands.gg repeats it, adding that 1 blocks Steam invites and the console `connect` command and that 0 allows joining mid-game (https://commands.gg/l4d2/sv-allow-lobby-connect-only; third party). Hobbyist-friend servers want 0 so friends can `connect ip:port` or use the server browser. A host (pingperfect) notes direct join fails when 1 (UNVERIFIED wording, could not open the original).
- `sv_search_key`: default empty, "When searching for a dedicated server from lobby, restrict search to only dedicated servers having the same sv_search_key." (cvar list). `sv_search_team_key` default `public`.
- `sv_steamgroup`: group ID, "You can find your group's ID on the admin profile page in the steam community"; `sv_steamgroup_exclusive` default 0: "only members of Steam group will be able to join the server when it's empty, public people will be able to join the server only if it has players." (cvar list).
- `sv_region`: default -1 ("The region of the world to report this server in"). Codes 0 east coast US ... 7 Africa, 255 world appear in a hosting KB (https://pingperfect.com/knowledgebase/534/Left-for-Dead-2-LFD2--Server-Configuration.html) and `sv_region 3` in FireDaemon's config; full code table from Valve is UNVERIFIED.
- `sv_lan` default 0: "Server is a lan server (no heartbeat, no authentication, no non-class C addresses)" (cvar list).
- Matchmaking cvars: `mm_dedicated_force_servers` "Comma delimited list of ip:port of servers used to search for dedicated servers instead of searching for public servers" (client side), `mm_dedicated_search_maxping` default 150 (cvar list). Lobby reservation: `sv_reservation_timeout` 120 s, `sv_reservation_grace` 5 s (cvar list). `sv_hosting_lobby` default 0 (no description).
- Mechanism of how a lobby-created game picks a dedicated server (needs `sv_gametypes` to include the lobby's mode; "sv_gametypes allows lobbies to start on your server, only for the mode you specify") is a Steam forum answer: https://steamcommunity.com/discussions/forum/13/1843566500518625515/ (single user reply, UNVERIFIED as official).
- 1up-servers: with `sv_allow_lobby_connect_only 0` friends join with the console command `connect <ip>:<port>`; "If a friend gets a lobby error, they used the matchmaking menu instead of `connect`"; leaving it at 1 means nobody reaches it by address (https://1up-servers.com/en/blog/l4d2-dedicated-server/). A Steam forum thread suggests the CLIENT command `mm_dedicated_force_servers "ip:port"` to make a lobby use a specific dedicated server; the thread never confirms it worked (https://steamcommunity.com/app/550/discussions/0/3211505894112076025). A `valve_reject_lan_game` error in the same thread was tied to `sv_lan` or port forwarding.
- Behind NAT: `net_public_adr` for servers behind NAT/DHCP exposed to the internet; `mm_dedicated_force_servers` uses `publicip:port|privateip:port` syntax (cvar list).

## Resources, Windows pitfalls, updates, panel must-nots
- Hardware (VDC Source Dedicated Server): at least 1.0 GHz CPU for a basic 20-slot server; at least 512 MB RAM, 1 GB enough for 60+ slots; "Windows 10/11 ... at least 4GB RAM". Bandwidth: upload only. Residential CGNAT may make hosting impossible. Disk: depots total ~9.7 GB (9,549,160,153 + 161,492,365 bytes, api.steamcmd.net).
- Updates: re-run the SteamCMD line with the server stopped; FireDaemon says run it about weekly and stop the server first. Windows `-autoupdate` is not supported (Linux only, VDC). Clients with a newer build cannot join an older server, so updating promptly matters (inference, UNVERIFIED).
- Panel must NOT: kill `srcds.exe` by image name (the same exe name is used by every Source dedicated server on the machine, VDC and Steam launch entry: all SRCDS-based apps use srcds.exe; match by PID). Do not run elevated: UNVERIFIED either way.
- Firewall: a Steam forum answer says one UDP port is enough (default 27015) and to allow srcds.exe through every firewall (Windows, router, antivirus) (https://steamcommunity.com/app/550/discussions/0/3592212630610414392, snippet only, also advises dropping `rcon_password` on home servers because RCON is insecure). The Steam community guide opens "UDP/TCP 27015-27050". Windows firewall prompt on first launch and VC++ redists: no source I opened covers them. UNVERIFIED.
- candidates.md notes a Steam forum "Invalid platform" error with anonymous login on non-Windows hosts; not re-opened. Windows is fine per FireDaemon.
