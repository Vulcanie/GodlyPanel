## Config files overview

| file | location (relative to the server install folder) | format | created by the game? | source |
|---|---|---|---|---|
| `SandboxSettings.ini` | `AbioticFactor\Saved\SaveGames\Server\Worlds\<WorldName>\SandboxSettings.ini` (one per world; default world folder name is `Cascade`, set by `-WorldSaveName=`). Can be redirected with the launch arg `-SandboxIniPath=` (path relative to the `\Saved\` folder, e.g. `Config/WindowsServer/Server1Sandbox.ini`). | INI. Must begin with the header line `[SandboxSettings]`; then `Key=Value` lines. Booleans written `True`/`False`. `;` starts a comment line (shipped example uses them). | UNVERIFIED. Docs (WGG, hosting guides) say "create it if it is missing"; LP says "By default this file is created per world save and is stored in that folder" but an open-then-closed GitHub issue (#58) reports the file not being generated. Panel should write the file itself and not assume it exists. A server restart is needed after edits (WGG). | GHW, LP, GHI, WGG, https://github.com/DFJacob/AbioticFactorDedicatedServer/issues/58 |
| `Admin.ini` | `AbioticFactor\Saved\SaveGames\Server\Admin.ini` (redirect with launch arg `-AdminIniPath=`, relative to `\Saved\`). | INI, section `[Moderators]`, one `Moderator=<SteamID64>` line per admin (repeated key). Steam players only; console players use `-AdminPassword=` instead. | UNVERIFIED. QS tells the user to "navigate to ... Admin.ini. Edit this file and add your SteamID under [Moderators]" after the server has run once, which suggests the game creates it on first run; XG says "create it if it doesn't exist". One hosting FAQ claims the server may wipe the entries at start (UNVERIFIED, single secondary source). | QS, LP, XG |

No other server config file is documented (no Engine.ini / GameUserSettings.ini / ServerSettings.ini mentioned in the official wiki). Server name, ports, passwords, max players and world name are launch arguments, not file settings (see LP; covered by the launch-arguments research step). The dedicated server console cannot change sandbox settings (WGG).

Minimal shipped content: the example file at GHI is the full 48-key list below, each key preceded by a `;` comment, starting with `[SandboxSettings]`. It is an example in the GitHub repo; whether the server install itself contains a copy is UNVERIFIED.

## UNVERIFIED

1. Whether the game itself writes `SandboxSettings.ini` on first run (docs conflict; issue #58 reports it was not created).
2. Whether the game writes `Admin.ini` on first run, and with what content; whether the entries can be wiped on start (single secondary hosting source).
3. Whether the server install ships a default `SandboxSettings.ini` (only the GitHub repo example is confirmed).
4. Upper bound of `StructuralSupportLimit`; labels for `BridgeSupports` values 1 and 2; the ranges for `BonusPerkPoints` (-20 to 50) and `BaseInventorySize` (0 to 42) which come only from a summarised view of the community wiki.
5. Minimum of `EnemyDeployableDamageMultiplier` (0 per official dedicated wiki, 0.1 per summarised community wiki).
6. Whether integer-choice settings accept values outside the listed ones, whether lowercase `true`/`false` works, and what the game does with out-of-range numbers (clamps or ignores).
7. Whether the game reads any key not in this list (the newest official wiki list has 48 keys and matches the shipped example one-to-one; new game patches may add keys; a GitHub issue "Update default SandboxSettings.ini to reflect additional settings" exists, indicating the list has grown over time).
8. Whether wiki.gg lists a "Main" group differently: its summary files `InvisibleRadiation` under "Main" rather than World; only a grouping difference.

## Found but not confidently explained

- `BridgeSupports` values 1 and 2 (official wiki leaves them blank).
- `StructuralSupportLimit` unit ("how much can be stacked" is all the docs say; the number's meaning, e.g. levels of stacked support, is not defined).
- `HardcoreMode` plus `AllowIronMode`: how Iron Mode appears for players is only described by the one line above.
- `ApocalypticAbilities` and `MaximizeEnemySpawns`: described, but the exact effect in play is not documented further.
- `DurabilityLossOnDeathMultiplier`: assumed to be a fraction of durability (0 to 1) from the min/max; the docs do not state the exact formula.
