Researched 2026-10-14. Dedicated server app 1110390 (store app 304930). Ground truth for every key, default and comment below is the game's own decompiled code, taken from the community datamining mirror https://github.com/Unturned-Datamining/Unturned-Datamining (branch `linux-client-preview`, `.buildid` file = 25613056, a PREVIEW-branch snapshot pushed 2026-10-14; the public branch may lag it slightly). Behaviour of the config loader is from `Provider.cs` and `PlayConfigUtils.cs` in the same repo. Official prose: https://github.com/SmartlyDressedGames/Unturned-Docs/blob/latest/servers/server-configuration.rst and server-hosting.rst (same folder). Cross-check of difficulty defaults against the wiki page https://unturned.wiki.gg/wiki/Difficulty (matched for every key I sampled: Food_Use_Ticks, Water_Use_Ticks, Experience_Multiplier, Lose_Skill_Levels_PvP, Detect_Radius_Multiplier, Items/Zombies Spawn_Chance, Chart, Ballistics, Has_Durability, Items Respawn_Time).

## READ FIRST: Config.json is the LEGACY file (important correction to the task premise)

- Since Unturned 3.25.8.0 the server's gameplay config is **`Config.txt`**, not `Config.json` (source: server-configuration.rst above, and https://restoremonarchy.com/servers/docs/config_json/overview deprecation notice). A brand-new server folder gets `Config.txt` and NO `Config.json`.
- `Config.json` is only (a) read once for conversion when an old server folder has it and no `Config.txt` exists yet (Provider.LoadGameplayConfig: converts only the active difficulty into `Config_<Easy|Normal|Hard>Difficulty.txt`, per server-configuration.rst), or (b) used and rewritten as-is when the server is started with the launch flag `-UseLegacyJsonGameplayConfig` (then the game serializes a full `Config.json`, all sections, with defaults, if none exists).
- **Where the file is:** `<U3DS install>\Servers\<ServerID>\Config.json` (or `Config.txt`), i.e. directly in the server folder, NOT in the `Server\` subfolder. Source: `PlayConfigUtils.GetServerConfigPathV2` = `Servers/<id>/Config.txt` and `ServerSavedata.populateJSON("/Config.json")` = `/Servers/<id>/Config.json` (code), and the wiki: "`.../U3DS/Servers/ServerName`". The `Servers\<ServerID>\Server\` subfolder holds `Commands.dat` (Provider.cs: `/Servers/<id>/Server/Commands.dat`), plus game-generated data. `WorkshopDownloadConfig.json` is in the server folder too (WorkshopDownloadConfig.cs: `ServerSavedata ... "/WorkshopDownloadConfig.json"`); its keys belong to the mods step, not here.
- **Recommendation for the panel:** edit `Config.txt` (key names are IDENTICAL to Config.json; PlayConfigUtils builds both from the same C# fields by reflection). Writing `Config.json` only works if the start script adds `-UseLegacyJsonGameplayConfig`, and the official docs list downsides of that (no comments, easy to break with missing commas, easy/normal/hard values side by side, level overrides win over defaults).
- **Does the game create it?** Yes, on first run `Config.txt` is generated with every option present and EMPTY (empty = use the default for the current difficulty), with explanatory comments prefixed by `>` (auto-generated; user comments with `//` are preserved). The game rewrites the file at startup on a worker thread, adding new options after updates. Flags: `-GameplayConfigNoGeneratedComments`, `-GameplayConfigNoEmptyValues`, `-GameplayConfigFile="X.txt"`, `-LogGameplayConfig`, `-NoLevelConfigOverrides` (all from server-configuration.rst; names confirmed in Provider.cs).

## Config.txt format (what a panel form would have to write)

From PlayConfigUtils.cs / Provider.cs: a Unturned "dat" text file. The game writes `Version 1` as the first value. Value lines are `Key Value` separated by whitespace (no equals sign, no quotes, no commas); `//` starts a comment, and comment lines starting `> ` are auto-generated explanations. Lists and nested blocks use `[ ]` and `{ }` (the doc comment on `Links` in BrowserConfigData.cs shows `Links` / `[` / `{` `Message ...` `URL ...` `}` / `]`). That the section blocks themselves use `{ }` is the standard dat nesting, but I did not see a sample generated file, so the panel should edit values inside the file the game generated rather than build one from scratch (see UNVERIFIED). Empty value = default. Wrong values give a console warning and fall back to the default.

Structure of `Config.txt` (PlayConfigUtils.ParseServerConfig / ParseModeConfig / PopulateConfigFilePropertiesAndComments): the root holds 13 named blocks: `Browser`, `Server`, `UnityEvents`, then `Items`, `Vehicles`, `Zombies`, `Animals`, `Barricades`, `Structures`, `Players`, `Objects`, `Events`, `Gameplay`. There is NO Easy/Normal/Hard nesting in `Config.txt`: one value per key, and the generated comment above each key lists the Easy/Normal/Hard defaults; an empty value uses the default of whichever difficulty the server runs. Only servers converted from a legacy `Config.json` get per-difficulty file names (`Config_<Easy|Normal|Hard>Difficulty.txt`). In legacy `Config.json` the layout is nested: top-level `Browser`, `Server`, `UnityEvents`, `Easy`, `Normal`, `Hard`, and each of Easy/Normal/Hard contains the ten mode sections `Items` ... `Gameplay` (ConfigData.cs, ModeConfigData.cs); only the block of the active difficulty is used.

Which difficulty is active: `Mode Easy|Normal|Hard` line in `Servers\<id>\Server\Commands.dat` (CommandMode.cs + ServerCommandMode.dat: "Mode [Easy | Normal | Hard]  This assigns the difficulty of the server."; can only be set before the server is running). Default is Normal (server-hosting.rst / restoremonarchy). Maps can override some of these values unless the player-set value is non-empty in Config.txt or `-NoLevelConfigOverrides` is used.

## How to read the tables

- All `key` spellings are exact (case-sensitive, underscores). Same keys in Config.txt and Config.json.
- "default" shows `Easy / Normal / Hard` when the code default depends on difficulty, otherwise one value (same for all). Defaults are from the C# constructors (`new XConfigData(mode)`), and "(not set in code)" means the field has no initializer, so it is the C# zero value (false/0).
- "Multiplier" = 1 means unchanged, 0.5 halves, 2 doubles.
- Units of "Ticks" settings are NOT stated in the game code or docs (UNVERIFIED seconds); only their direction is known (lower = faster).
- 282 settings are documented in total across all sections (Browser, Server, UnityEvents, then the ten per-difficulty sections). Each of the ten per-difficulty sections exists once per difficulty in Config.json (Easy, Normal, Hard), so 282 is the count of section/key entries (the same key name, such as Spawn_Chance, appears in several sections), and Config.json holds three copies of the mode sections. The nested Links entry fields (Message, Url/URL) are covered inside the Links row. A reflection check against the C# classes found no field missing from the tables.
- Every row's source is the C# class listed in the section heading (doc comments in the class were used for meaning; where I paraphrased I kept to those comments).
